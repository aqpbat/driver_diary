### Решения, принятые ИИ на этом этапе без вопроса

- `Validate` возвращает одну ошибку на поле (`map[поле]сообщение`), но по всем полям сразу.
- `commission > amount` сообщается только при корректной сумме — иначе на одно неверное `amount` приходило бы две ошибки.
- `id` из одних пробелов считается пустым; длина `id` считается в символах, а не в байтах.
- Разбивка по оплате — структура с полями `cash`/`card`, а не словарь: оба ключа гарантированно есть в JSON.
- Имя Go-модуля — `driverdiary` (адрес репозитория на момент написания неизвестен).

## 2026-10-06 — этап 2: хранилище и HTTP (C, D4–D9)

- **Что спросили:** реализовать второй этап по чеклисту.
- **Что получили:**
  - `api/internal/store` — пул `pgxpool`, ожидание базы при старте, миграции и начальные данные под `pg_advisory_lock`, `Add` / `ByDay` / `Days`;
  - `api/internal/httpapi` — маршруты, единый формат ошибок, CORS, лог запросов;
  - `api/cmd/server` — конфиг из env, graceful shutdown, флаг `-healthcheck`;
  - `api/internal/testdb` — отдельная схема PostgreSQL на каждый тест;
  - тесты: дубли (повтор, конфликт, другое смещение, гонка из 50 горутин), повторное открытие хранилища, одновременный старт пяти экземпляров, согласие SQL и Go по границам дня, `CHECK` в базе, все маршруты через `httptest`.
- **Проверено запуском, а не только тестами:** собранный бинарник на локальном PostgreSQL — `201` → `200` → `409`, повтор после перезапуска сервера всё ещё `200`, `-healthcheck` возвращает 0 при работающем сервере и 1 после остановки.
- **Ошибки ИИ:** _заполнить по итогам ревью_
- **Руками:**
  - [ ] прочитать `store.Add` и `prepare.go` — на них держится защита от дублей и однократность миграций;

### Решения, принятые ИИ на этом этапе без вопроса

- Неверный тип поля (`"amount": "2400"`, `2400.5`), время не в RFC 3339 и лишнее поле — это `422` с указанием поля, а не `400`. `400` остаётся только для тела, которое не является одним JSON-объектом.
- Добавлены коды, которых не было в контракте: `413` (тело больше 64 КБ), `404` и `405` в общем формате ошибок, `503` у `/healthz` — тоже в общем формате.
- Время обрезается до микросекунд перед записью: PostgreSQL хранит микросекунды, и без этого повтор поездки с наносекундами получал бы `409` вместо `200`.
- `id` с управляющими символами отклоняется в `Validate` (байт NUL нельзя записать в `TEXT`, иначе было бы `500`).
- В `internal/trip` добавлены `DayBounds`, `DayCount` и `AddOutcome`, чтобы `httpapi` не импортировал `store` и через него `pgx`.
- `store.ByDay` принимает границы дня, а не дату: строку разбирает `trip.DayBounds`, он же даёт `400` на кривую дату.
- Размер пула (10), ожидание базы (30 с) и таймаут запроса (5 с) заданы константами, без переменных окружения.
- Подставное хранилище используется только в тестах на `500`/`503`, `404`/`405` и CORS; всё, что касается данных, идёт на PostgreSQL.
- Без `TEST_DATABASE_URL` `go test ./...` печатает `ok`: сообщение о пропуске видно только с `-v`. В CI (переменная `CI`) такие тесты падают.
